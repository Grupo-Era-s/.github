# Contribuindo com projetos da ERA&S

Este documento define um padrão simples para manter os projetos organizados.

## Antes de alterar um projeto

1. Entenda qual repositório e pasta serão modificados.
2. Rode o projeto localmente quando possível.
3. Não envie arquivos `.env`, senhas, tokens ou chaves de API.
4. Evite misturar várias mudanças sem relação no mesmo commit.

## Commits

Use mensagens curtas e objetivas. Exemplos:

- `feat: adiciona formulário de contato`
- `fix: corrige menu no mobile`
- `style: ajusta seção de serviços`
- `docs: atualiza README`
- `refactor: reorganiza componente Header`

## Branches

Quando o fluxo com branches estiver sendo usado, prefira nomes como:

- `feature/agendamento`
- `fix/menu-mobile`
- `docs/readme`

## Antes de integrar uma mudança

- Confira se o projeto continua funcionando.
- Revise os arquivos alterados.
- Explique de forma simples o que mudou.

Este padrão deve continuar leve. A equipe pode aumentar o nível de controle conforme os projetos e o conhecimento de Git/GitHub evoluírem.
